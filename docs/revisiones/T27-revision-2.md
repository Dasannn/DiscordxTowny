## Findings

- **F3 — blocking — `src/main/java/com/discordtowny/discord/JdaGuildOperationExecutor.java:372-375, 397-400`.** `guild.getTextChannelById` and `getVoiceChannelById` read [JDA's channel cache](https://docs.jda.wiki/net/dv8tion/jda/api/entities/Guild.html); they do not make the claimed second request to Discord. If Discord deletes a source channel after the first lookup, the move returns `UNKNOWN_CHANNEL`, but its deletion gateway event has not yet reached the cache (or the gateway is disconnected), the re-check still returns the cached object. The catch rethrows, `classifyError` returns `PERMANENT_FAILURE`, and `onOperationFailed` leaves the space `INCONSISTENT`. `DefaultSyncService.reconcileSingleSpace` retries deleted or ruined towns whose state is not `ARCHIVED`, reopening the T27 loop for this race. Conversely, a `null` cache result can reflect lost visibility or an invalidated cache while the source still exists; treating that as proof of deletion could save `ARCHIVED` with an unmoved channel. The non-null mistake is conservative about channel state but noisy and can repeat forever; the null mistake is unsafe because it hides unfinished work. The new tests assert outcome and stored state for both branches, but their sequential mock returns assume the cache has already learned the deletion. Disambiguate with authoritative evidence of source absence, or otherwise keep the operation retryable until the source or destination is known; test a stale source cache after a real `UNKNOWN_CHANNEL`.

## Checks without findings

- `channelsNeeded == 0` skips archive-category creation, so an archive with no surviving channels is not refused. If a category is full, `ensureCategoryWithCapacity` advances to a numbered category; if none exists, it creates one. The new null guard fires only when channels need moving and category creation returns `null`. Its permanent failure is appropriate for unfinished work.
- Removing `ArchiveSpace` from the outer `UNKNOWN_CHANNEL`/`UNKNOWN_ROLE` success branch is appropriate for uncaught errors: a failure before the state save cannot be called a completed archive. Missing role deletion is still swallowed locally, and initially absent channels never reach the move. The race in F3 is the remaining genuinely absent source path that this change misclassifies.
- F2 preserves a nonblank Towny reason and appends the note; a null or blank reason uses the note alone. With no note, it preserves the old reason value, including blank. Audit detail is stored in a `TEXT` column and consumed as display text by the Discord log; no downstream parser was found. The usual Towny reasons are short. An arbitrarily long reason could exceed the Discord embed description limit because rendering checks length only after appending a whole event; this pre-existing renderer limit is not a T27 blocker.
- The new tests check success/failure and `ARCHIVED`/`INCONSISTENT` saves for source missing versus destination missing; they do more than verify a lookup call. The null-category and both-channels-missing cases are covered by earlier T27 tests.
