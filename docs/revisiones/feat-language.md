# T14 review — feat/language

Reviewed against spec section 9.1, acceptance criterion 12, the T14 card, and constitution P9. Static review only; no git or Gradle commands were run. The architect reports a green build with 275 tests (previously 242); that result was not independently executed here.

## Findings

- **important** — `src/main/java/com/discordtowny/config/YamlMessages.java:34` and `:37`: Both resolution stages accept empty or whitespace-only strings. An owner setting a reply to `""` receives only the prefix, without an English fallback or warning; setting the prefix empty too produces a completely blank reply. An empty English fallback likewise suppresses the visible missing-key marker. Ensure unusable reply text proceeds through the fallback chain and ultimately produces a visible marker; preserve the ability to omit the decorative prefix. Add coverage for blank selected and fallback replies.
- **important** — `src/main/java/com/discordtowny/config/YamlConfigLoader.java:119`, `:134`, and `:87`: A corrupt or unreadable selected message file adds a fatal configuration problem, so `load()` throws before publishing the English fallback. With otherwise valid configuration, startup cannot obtain its configuration; a reload retains the previous language instead of recovering. Separate message-file failures from fatal configuration validation, name the failing file in an English warning, and continue using bundled English and visible placeholders. Test a malformed message file with a valid config; the existing test at `src/test/java/com/discordtowny/config/YamlConfigLoaderTest.java:240` also deletes config.yml and therefore does not isolate this requirement.
- **important** — `src/main/java/com/discordtowny/config/YamlConfigLoader.java:89`: Reload replaces the `Messages` instance, while `src/main/java/com/discordtowny/discord/LinkSlashCommands.java:36` retains it in a final field and `src/main/java/com/discordtowny/minecraft/LinkMinecraftCommands.java:54` captures it in command handlers. Calling `load()` after switching languages therefore leaves already-created handlers replying in the old language. Ensure existing consumers observe successful language reloads without changing the `Messages` interface, and test a retained consumer/reference across reload. The test at `src/test/java/com/discordtowny/config/YamlConfigLoaderTest.java:375` reacquires `loader.messages()` after every load and misses this behavior. Actual `/dt admin reload` registration and startup wiring are absent in this snapshot; coordinate that integration with the architect/T8 rather than silently expanding the author's zone.
- **important** — `src/main/java/com/discordtowny/minecraft/LinkMinecraftCommands.java:67`, `:99`, and `:142`: Console execution of `/dt link`, `/dt unlink`, or `/dt admin unlink` routes replies through the selected `Messages`, so `language: es` produces Spanish console output. The admin path also localizes its working, success, and failure replies. Ensure console recipients use English independently of player language and verify both console and player execution. This requires coordination outside the T14 file zone; diagnostic logger strings themselves are English.
- **minor** — `src/main/java/com/discordtowny/discord/LinkSlashCommands.java:57`, `:59`, and `:62`: Slash-command and option descriptions are hard-coded English and have no keys in either catalog. With Spanish selected, players still see English in Discord's command interface. T14 explicitly requires reporting missing texts instead of inventing them: have the architect assign the missing catalog entries and language-aware registration work, preserving the `code` option name and legacy `codigo` reader.

## Checks and limits

- Missing keys in an existing valid file reach bundled English, not the owner's English file; keys missing from both maps receive `[missing message: key]`. A completely empty YAML file loads an empty map and therefore falls back correctly. This differs from an explicitly blank value, covered above.
- Deleting `messages_es.yml` with `language: es` normally recreates the bundled Spanish file before reading it (`YamlConfigLoader.java:84`). If recreation fails, the unreadable-file finding applies. Existing files, including outdated ones, are skipped by `Files.notExists`; copying has no replacement option. Neither reload nor a new loader replaces an existing owner's file based on version or age.
- The warned-key set is an instance field (`YamlMessages.java:19`), and `missing.add(key)` guards the warning. Repeated calls on one loaded instance do not flood the console. A successful reload creates a new set, so the same missing key can warn again after reload; it is not recreated per call.
- Unknown non-null language values warn with `language`, list `[en, es]`, and select English without adding a validation problem (`YamlConfigLoader.java:107`). Missing language defaults to English. Other invalid configuration can still reject the load independently.
- Independently checked the current catalogs with a read-only script: 43 string keys each, no key differences, and no placeholder-set differences. The test at `YamlConfigLoaderTest.java:306` constructs and compares both complete string-key sets. The placeholder test compares both placeholder sets per English key; together these tests cover both directions.
- `firstRunWritesBothFilesAndNeverOverwritesAfterwards` checks the exact edited string including its newline (`YamlConfigLoaderTest.java:370`), not merely existence. For its ASCII fixture this verifies the expected content exactly; it does not exercise Spanish edits, a new loader simulating restart, or arbitrary byte encodings. The implementation's non-replacing copy supports preservation on those restart/update paths.
- Reviewed all current English/Spanish text pairs, including code expiration, unlink role removal, archive confirmation, history restoration, automatic retry, checksum rejection, and permanent purge. No semantic translation drift was found. Archive wording agrees with spec section 7's lifecycle behavior. Historical text-for-text identity with the old messages.yml cannot be established without an old-content baseline; no git history was accessed, and no claim of historical identity is made.
- The current `Messages` contract remains `get(key, placeholders)`, its default `get(key)`, and `plain(key, placeholders)`; callers use that shape without a language argument. Historical signature equality cannot be independently established without a baseline. `PluginConfig` retains an old-shape constructor defaulting language to English.
- `/link` registers `code` (`LinkSlashCommands.java:58`), reads it first, and then reads `codigo` when absent (`:117`). Tests exercise both names through mocked events and redemption, including the new direct `code` test. Neither spelling requires the player to change an already-registered legacy guild command.
- The current plugin entry point does not instantiate the loader (`DiscordTownyPlugin.java:18`), so first-run file extraction and end-to-end command reload are only demonstrated at loader level, not through a running plugin. This is an integration limitation of the snapshot, not an independently established T14 regression.

Final verdict: needs corrections
